# VSN Virtual Microphone Test Package

This directory contains the development INF for the VSN virtual capture endpoint. It is a test-install boundary only. It does not constitute Microsoft production signing, WHQL/HLK certification, release approval, or evidence that the endpoint has been installed on supported user hardware.

## Package contents

A built test package contains:

- `vsn_virtual_mic.inf` — MEDIA-class root-enumerated capture device package metadata.
- `vsn_virtual_mic_control.sys` — the WDK-built VSN PortCls/KMDF driver binary.
- `vsn_virtual_mic.cat` — an unsigned catalog generated by Inf2Cat, or a test-signed catalog when an explicitly supplied local test certificate is used.

The INF registers only the `VSNWave` capture/realtime/audio interfaces and `VSNTopology` audio/topology interfaces implemented by the driver. It does not advertise a render endpoint.

## Build and verify

From an elevated PowerShell prompt with the Windows SDK/WDK installed:

```powershell
./scripts/windows/build-virtual-mic-test-package.ps1 `
  -DriverBinary <path-to-vsn_virtual_mic_control.sys>
```

The script copies the driver and INF to an isolated staging directory, runs `InfVerif /w`, and runs Inf2Cat for the declared x64 Windows targets. CI executes the same package build without a signing certificate.

## Optional local test signing

No certificate, private key, PFX, password, or production signing material belongs in this repository. If a developer has already created and installed an authorized code-signing test certificate in the local certificate store, the catalog can be signed by passing its thumbprint:

```powershell
./scripts/windows/build-virtual-mic-test-package.ps1 `
  -DriverBinary <path-to-vsn_virtual_mic_control.sys> `
  -CertificateThumbprint <local-test-certificate-thumbprint>
```

The script uses SignTool with SHA-256 and the local certificate store. It deliberately does not create, export, upload, or persist certificate material.

## Controlled test installation

Use a disposable Windows test machine or VM. Do not install development packages on a production workstation.

1. Configure the test machine for the organization's approved Windows driver test-signing policy and reboot if required.
2. Install/trust only the approved local test certificate used to sign the catalog.
3. Stage the package with an elevated prompt:

   ```powershell
   pnputil /add-driver .\vsn_virtual_mic.inf
   ```

4. Create the root-enumerated development device with a WDK-provided DevCon build when the test environment uses the root-device workflow:

   ```powershell
   devcon install .\vsn_virtual_mic.inf ROOT\VSNVIRTUALMIC
   ```

5. Verify Device Manager and Windows audio endpoint enumeration. Only after the endpoint is visible should the runtime `DeviceIoControl` handshake and approved calling-application routing smoke tests be executed.
6. Remove the development device/package after testing using the test environment's device/package cleanup procedure.

Production signing, release distribution, hardware compatibility certification, and customer installation remain separate release-gated work.
